# limits

Личная команда: лимиты Claude и Codex, тарифы и даты подписок в одном терминале.
Python 3.9+, без дополнительных зависимостей. Локальный Git; remote не нужен.

```sh
limits                 # живой экран: ↑↓ или цифра — выбрать аккаунт Claude,
                       # Enter — переключиться, Esc — снять выбор, c — стоимость,
                       # r — обновить, q — выход
limits --cost          # сразу экран стоимости: сколько стоят 1% и 100% окна
limits --history       # итог каждого прошлого окна Claude по датам
limits --once          # один кадр (с --cost — кадр стоимости)
limits --json          # один снимок, включая ошибки отдельных аккаунтов
                       # (с --cost — расход и оценки в поле cost каждого окна Claude)
limits --no-color
```

## Экран

Таблица в два раздела, CLAUDE и CODEX. Слева колонка аккаунта: имя, под ним
тариф и дата подписки. Номер слота есть только у Claude (для `cswap switch`),
`● активный` отмечает текущий аккаунт. Общий для всех адресов домен не
показывается. Справа по строке на окно: процент, полоса, время до сброса
(столбец «сброс через»). `▲ кончится через ~1h 6m` — прогноз cswap
(`projectedExhaustionAt`), что лимит кончится раньше сброса; `▲ быстрее нормы` —
опережение без прогноза. Прогноз показывается только у активного аккаунта Claude:
провайдеры считают его по среднему темпу с начала окна, и у простаивающего
аккаунта он не убывает. У Codex прогноза нет по той же причине. `■ исчерпан`
виден у всех. В узком окне пометка переносится под полосу. Дата подписки в
ближайшие 5 дней выделяется жёлтым с числом дней. В заголовке вкладки живого
экрана — сводка по активному аккаунту: `limits · alice 36%`, с `▲` при прогнозе
или исчерпании. Возраст данных показывается только старше 15 минут:
cswap штатно держит кэш неактивных аккаунтов несколько минут. Источник даты
подписки и точное время окончания периода есть в `limits --json`.

Живой экран открывается поверх терминала (как `less`) и при выходе возвращает
прежнее содержимое. Enter на выбранном аккаунте вызывает `cswap switch N --json`
и сразу показывает результат или ошибку cswap. Источники опрашиваются в фоне:
экран не ждёт CodexBar, а выход не ждёт незавершённого опроса. Последние цифры
Codex хранятся в `~/.cache/limits/codex.json` (права 0600, `XDG_CACHE_HOME`
учитывается) и показываются при запуске с их возрастом, пока идёт свежий опрос.
Это собственный файл `limits`; приложение CodexBar запускать не нужно, вызывается
только его консольный помощник.

Claude читается через установленный `cswap list --json` каждые 60 секунд.
Codex — через CodexBar каждые 300 секунд. Дополнительно обнаруживаются профили
`~/Library/Application Support/orca/codex-accounts/*/home`.
Повторные профили одного email и workspace объединяются. Отсутствие лимитов
или ошибка входа оставляет аккаунт на экране. При временном сбое сохраняются
последние цифры с исходным временем и видимой ошибкой; для Claude — сразу после
запуска, из `lastGoodUsage` cswap. Если cswap ответил ошибкой, выводится его
сообщение. Если момент сброса уже прошёл, а цифры ещё из кэша (у неактивных
аккаунтов cswap держит их минутами), окно показывается сброшенным: 0%, у недельных
окон Claude следующий сброс через 7 дней, как в меню cswap; у 5h и у Codex —
без времени до нового замера.

Для CodexBar создаётся временный конфиг с дополнительными `codexProfileHomePaths`.
Настройки CodexBar, системный аккаунт и входы Orca не переключаются. Токены не
копируются в конфиг, вывод или репозиторий; сетевые запросы выполняет CodexBar.
Сам CodexBar может делегировать обновление устаревшего входа штатному Codex CLI.
Контракт: [CodexBar 0.62.0, profile homes](https://github.com/steipete/CodexBar/blob/v0.62.0/docs/codex.md#advanced-profile-home-accounts).

## Стоимость

Клавиша `c` (или `с`, `$`) переключает экран: вместо полос у окон Claude два
столбца — «за 1%» и «за 100%»: цена по API и число токенов. Например,
`$23.8 · 62M   $2,384 · 6.2B` значит, что процент недельного окна стоил около
$23.8 по прайсу API и 62 млн токенов, а всё окно — около $2.4k и 6.2 млрд токенов.
Токены считаются все: вход, выход, запись и чтение кэша (чтение кэша — основная
их часть). Столбец «модели» показывает, на какие модели ушли деньги окна
(`Opus 5.5 89% · Fable 5.1 11%`); полная разбивка $ и токенов по моделям — в
`limits --json --cost` (поле `models`) и в истории. В узком терминале сначала
пропадает столбец моделей, затем токены; цены остаются. У Codex столбцы пустые,
его токены не считаются.

Расчёт: расход в окне ÷ процент окна. Расход берётся из транскриптов Claude Code
(`~/.claude/projects/**/*.jsonl`, включая сабагентов и сессии вкладки Code в Claude
Desktop) и оценивается по ценам API с учётом модели, чтения кэша и записи на
5 минут и на час (таблица `PRICES` в `worth.py`, цены на 25.09.2026). Окно
начинается в момент сброса минус 5 часов или 7 дней и заканчивается в момент,
когда cswap прочитал процент (не позже сброса): расход после замера в процент ещё
не попал. Окно Fable учитывает только модели Fable. Fast mode не учитывается:
на подписке он оплачивается из usage credits и в лимиты не входит.

Ответ модели пишется в транскрипт несколько раз по мере стриминга; считается он
один раз, по копии с наибольшим выходом. У части ответов, почти всегда в
транскриптах сабагентов, финальной копии нет и известен только выход начала
стрима (обычно около 10 токенов). Им подставляется средний выход законченных
ответов той же модели; сколько токенов подставлено — в JSON
(`estimated_output_tokens`). На 03.10.2026 подстановка добавила к окнам от долей
процента до ~18% (окно Fable у alice, где много сабагентов).

В транскриптах нет аккаунта, поэтому расход относится к аккаунту так:

- сессии Claude Desktop — к аккаунту, под которым Desktop их хранит
  (`~/Library/Application Support/Claude/claude-code-sessions/<user>/<org>/`);
  Desktop работает под своим входом, а не под аккаунтом cswap;
- всё остальное — к аккаунту, на который cswap переключил Claude Code к этому
  моменту (журнал `~/.claude-swap-backup/claude-swap.log*`, в том числе
  «Activated account»). Если cswap пишет, что вход сменился без него (например,
  Orca или `/login`), с момента смены и до следующего переключения расход не
  относится ни к кому и попадает в `unattributed_usd` в JSON. Это видно, только
  пока cswap опрашивает вход: при открытом `limits` — раз в минуту.

Не проверено, под каким аккаунтом работают процессы, запущенные из сессии
Desktop без её записи: `claude -p` арены и сессии, удалённые из Desktop. Сейчас
они относятся к аккаунту cswap, их доля в окне — в JSON
(`unrecorded_desktop_usd`); 03.10.2026 это была половина окна Fable у
bob. Проверка: когда Desktop и cswap на разных аккаунтах, в сессии
Code в Desktop выполнить `claude auth status` и сравнить email с `cswap list`.

Точность. Видно только то, что выполнялось на этом Mac: claude.ai, телефон,
облачные сессии и другие машины тратят те же лимиты незаметно, поэтому оценка
занижена, и тем сильнее, чем больше работы шло мимо этого Mac. Цена в $ зависит
от смеси моделей и доли чтения кэша, поэтому $/1% меняется и без изменения
лимитов. Процент целый: при окне меньше 10% цифры помечены `~` и блёклые; при 0%
или без локального расхода стоит `—`; на 100% процент, возможно, упирается в
потолок. Запущенный Claude Code видит переключение cswap с задержкой до
~30 секунд. Сверка 03.10.2026: два аккаунта Max 20x дали неделю $2,497 и $2,734
(разница 9%), окно Fable — $817 и $893; пятичасовое окно Max 5x ($194) — около
четверти окна Max 20x ($726). Это согласованность за одну неделю, а не проверка
точности.

Живой экран считает расход в фоне раз в минуту при любом виде, чтобы история
пополнялась; читаются только новые строки транскриптов. Индекс за последние
8 дней лежит в `~/.cache/limits/usage.sqlite3` (права 0600, `XDG_CACHE_HOME`
учитывается). Первый проход по неделе (~4 ГБ) занимает 10–20 секунд, следующие —
доли секунды. Индекс хранит время, модель, сессию и счётчики токенов, без текста.
Удаление файла безопасно: индекс соберётся заново.

## История

Каждая оценка сохраняется в `~/.local/share/limits/history.jsonl` (права 0600,
`XDG_DATA_HOME` учитывается; это не кэш, файл не удалять). Строка пишется, когда
процент окна вырос: у недельных окон на каждый пункт, у пятичасового — на каждые
5, и один раз на 100%. В строке: время, аккаунт, тариф, окно и его сброс,
процент, момент замера, расход в $ и токенах (всего и по моделям), неотнесённый
расход, расход сессий Desktop без записи, подставленный выход и оценки 1% и 100%.
Строки одного окна — его ход; итог окна — строка с наибольшим процентом (первая,
если их несколько). Несколько процессов (`limits` в двух терминалах, периодический
запуск) пишут в файл по очереди и не повторяют строки друг друга.

`limits --history` показывает итог каждого окна: недельные окна — все, по тарифам,
от старых к новым; пятичасовые — последние 12 с процентом от 10. «идёт» — окно
ещё не сброшено, и оценка может уточниться. Так можно искать урезание лимитов и
разницу между неделями, но надёжно видны только крупные изменения, примерно от
20%: доля работы мимо этого Mac, смесь моделей и кэша сами двигают $/1% (см.
«Точность»). Точнее сравнивать ход окна: прирост расхода между двумя строками ÷
прирост процента не зависит от того, что было потрачено до начала записи. История
пишется, только пока открыт `limits` или вызывается `limits --cost`; для
непрерывной записи можно поставить периодический запуск
`limits --json --cost > /dev/null` (например, launchd раз в 15 минут).

## Подписки

Для Codex читается **сохранённое** поле `chatgpt_subscription_active_until` из
метаданных входа; дата его проверки провайдером лежит в `limits --json`.
Это не свежий запрос в биллинг. Выбирается самая свежая проверка одного workspace;
дата не переносится на другой workspace. Срок токена и сроки reset credits
никогда не используются как дата подписки.

cswap не отдаёт дату продления Claude. Подтверждённые в Billing даты задаются так:

```sh
limits --set-subscription claude user@example.com 2026-10-14 --renews
limits --set-subscription codex user@example.com 2026-10-10
```

Первый вариант означает автопродление, второй — окончание известного оплаченного
периода. `--subscription-source` позволяет подписать источник. Это только
локальная запись даты, без оплаты и изменений подписки. Даты находятся в
`~/.config/limits/subscriptions.json` (права 0600); переопределение пути —
`LIMITS_SUBSCRIPTIONS`. После изменения даты перезапустите уже открытый экран.
Прошедшая дата выделяется пометкой «проверь» и не переносится на
следующий месяц автоматически. Если даты нет, выводится «нет даты подписки».

## Разработка

Исходная версия импортирована без изменений из OpenClaw integrations/limits.
Рабочая команда `~/.local/bin/limits` запускает `watch.py` из основной ветки этого
репозитория. `/opt/homebrew/bin/limits` — существующая ссылка на ту же команду.
Изменения делаются в отдельном worktree, затем сливаются в main.

```sh
/usr/bin/python3 -m unittest -v
```

Проверки покрывают потерянные/ошибочные аккаунты, частичный отказ CodexBar,
объединение профилей, разграничение workspace, возраст данных, даты подписок,
компактный вывод пяти аккаунтов в терминале 120×24, целый прогноз на ширине 80 и 100,
сброшенные по расписанию окна, последние данные и ошибки cswap, клавиши, выбор
аккаунта, переключение через cswap, кеш Codex и стоимость: индекс транскриптов
(копии одного ответа, флаги fast и финальной копии, недописанная строка,
перезапись и подмена файла, очистка старого), цены, журнал cswap (смена слотов,
Activated, время чужого входа), отнесение расхода к аккаунтам (CLI, Desktop,
запуск из Desktop, неизвестный аккаунт, окно Fable, конец окна в момент замера,
fast mode, подстановка выхода), экран стоимости, модели и узкий терминал, история
(шаги записи, одна строка на 100%, продолжение после перезапуска, строки другого
процесса, итог окна, отчёт).
