# limits

Личная команда: лимиты Claude и Codex, тарифы и даты подписок в одном терминале.
Python 3.9+, без дополнительных зависимостей.

```sh
limits                 # живой экран: ↑↓ или цифра — выбрать аккаунт Claude,
                       # Enter — переключиться, Esc — снять выбор, s — статистика,
                       # r — обновить, q — выход
limits --once          # один кадр
limits --json          # один снимок, включая ошибки отдельных аккаунтов
limits --stats         # статистика Claude: сколько стоят 1% и 100% окон, по неделям
                       # (с --json — данными)
limits --observe       # записать текущие проценты для статистики и выйти
limits --no-color
```

## Экран

Таблица в два раздела, CLAUDE и CODEX. Слева колонка аккаунта: имя, под ним
тариф и дата подписки. Номер слота есть только у Claude (для `cswap switch`),
`● активный` отмечает текущий аккаунт. Общий для всех адресов домен не
показывается. Справа по строке на окно: процент, полоса, время до сброса
(столбец «сброс через»). `▲ кончится через ~1h 6m` — прогноз cswap
(`projectedExhaustionAt`), что лимит кончится раньше сброса; `▲ быстрее нормы` —
опережение без прогноза. Прогноз показывается только у активного аккаунта Claude:
провайдеры считают его по среднему темпу с начала окна, и у простаивающего
аккаунта он не убывает. У Codex прогноза нет по той же причине. `■ исчерпан`
виден у всех. В узком окне пометка переносится под полосу. Дата подписки в
ближайшие 5 дней выделяется жёлтым с числом дней. В заголовке вкладки живого
экрана — сводка по активному аккаунту: `limits · alice 36%`, с `▲` при прогнозе
или исчерпании. Возраст данных показывается только старше 15 минут:
cswap штатно держит кэш неактивных аккаунтов несколько минут. Источник даты
подписки и точное время окончания периода есть в `limits --json`.

Живой экран открывается поверх терминала (как `less`) и при выходе возвращает
прежнее содержимое. Enter на выбранном аккаунте вызывает `cswap switch N --json`
и сразу показывает результат или ошибку cswap. Источники опрашиваются в фоне:
экран не ждёт CodexBar, а выход не ждёт незавершённого опроса. Последние цифры
Codex хранятся в `~/.cache/limits/codex.json` (права 0600, `XDG_CACHE_HOME`
учитывается) и показываются при запуске с их возрастом, пока идёт свежий опрос.
Это собственный файл `limits`; приложение CodexBar запускать не нужно, вызывается
только его консольный помощник.

Claude читается через установленный `cswap list --json` каждые 60 секунд.
Codex — через CodexBar каждые 300 секунд. Дополнительно обнаруживаются профили
`~/Library/Application Support/orca/codex-accounts/*/home`.
Повторные профили одного email и workspace объединяются. Отсутствие лимитов
или ошибка входа оставляет аккаунт на экране. При временном сбое сохраняются
последние цифры с исходным временем и видимой ошибкой; для Claude — сразу после
запуска, из `lastGoodUsage` cswap. Если cswap ответил ошибкой, выводится его
сообщение. Если момент сброса уже прошёл, а цифры ещё из кэша (у неактивных
аккаунтов cswap держит их минутами), окно показывается сброшенным: 0%, у недельных
окон Claude следующий сброс через 7 дней, как в меню cswap; у 5h и у Codex —
без времени до нового замера.

Для CodexBar создаётся временный конфиг с дополнительными `codexProfileHomePaths`.
Настройки CodexBar, системный аккаунт и входы Orca не переключаются. Токены не
копируются в конфиг, вывод или репозиторий; сетевые запросы выполняет CodexBar.
Сам CodexBar может делегировать обновление устаревшего входа штатному Codex CLI.
Контракт: [CodexBar 0.62.0, profile homes](https://github.com/steipete/CodexBar/blob/v0.62.0/docs/codex.md#advanced-profile-home-accounts).

## Статистика

Клавиша `s` (или `ы`) открывает отдельный экран: сколько в $ по ценам API и в
токенах стоят 1% и 100% окон Claude, по аккаунтам, тарифам и неделям. Главный
экран при этом не меняется. Вкладки переключаются цифрами `1–4` или `←→`, `↑↓`
прокручивают, `r` пересчитывает, `s` или `Esc` возвращают назад. Без живого
экрана: `limits --stats` печатает все вкладки, `limits --stats --json` — данные.

- **Сейчас** — текущие окна каждого аккаунта: процент, с какого момента считаем
  (`↺` — процент начался заново посреди окна), потрачено, за 1% и за 100% с
  диапазоном, то же без чтения кэша, способ, модели.
- **Недели** — главная вкладка: недельные окна и окна Fable по тарифам, от старых
  к новым, со строкой итога по точным замерам.
- **5 часов** — последние пятичасовые окна, дошедшие до 30% или до упора.
- **Данные** — на чём стоят цифры: сколько расхода оценено или отнесено с
  оговорками, сверка аккаунтов, перезапуски, история тарифов, покрытие замеров.

Автоматических выводов об «урезании» лимитов нет: только таблицы для сравнения.

### Как считается

Хранятся факты, оценки каждый раз выводятся из них заново.

- **Расход** — ответы моделей из транскриптов Claude Code
  (`~/.claude/projects/**/*.jsonl`, включая сабагентов и вкладку Code в Claude
  Desktop) по ценам API с учётом модели, чтения кэша и записи на 5 минут и на час
  (таблица `PRICES` в `worth.py`, цены на 25.09.2026; у неизвестной модели цены
  нет, и она показана на вкладке «Данные»). Fast mode не входит: на подписке он
  оплачивается из usage credits. Транскрипты хранятся годами, поэтому индекс за
  90 дней в `~/.cache/limits/usage.sqlite3` можно удалить: он соберётся заново
  (первый раз около минуты, потом секунды).
- **Проценты, тарифы и связи «сессия Desktop → аккаунт»** задним числом не
  узнать. Они дописываются в `~/.local/share/limits/observations.jsonl` (права
  0600, файл не удалять) при каждом опросе cswap, пока открыт `limits`: строка,
  когда изменился процент или сброс, и перед ней последний замер прежнего значения.
  Тариф берётся из живого профиля активного аккаунта: сохранённая копия cswap
  отстаёт после смены тарифа.

Окно делится на **отрезки**: новый начинается со сброса окна или с перезапуска
процента (смена тарифа, сброс лимитов со стороны Anthropic). Перезапуск виден
двумя способами: замер ниже предыдущего в том же окне или расход, который
всерьёз продолжился после упора в лимит и до сброса. Перезапуск одного окна
делит все окна аккаунта. У каждого отрезка — лучший из трёх замеров:

- **упор** — первое сообщение «You've hit your … limit»: ровно 100% в эту секунду,
  без округления. Работает и за дни, когда `limits` был закрыт;
- **разность** — расход между двумя замерами ÷ разность процентов, если начало
  отрезка не наблюдалось, а между замерами не меньше 20 пунктов;
- **уровень** — расход с начала отрезка ÷ процент.

Диапазон в скобках — от целого процента (±1 пункт) и от расхода с неясным
аккаунтом; `~` — меньше 10 пунктов. «100%» всегда значит «при такой же работе»,
а не баланс в долларах, заданный Anthropic.

**Чей расход.** В транскриптах нет аккаунта. Сессии Claude Desktop относятся к
аккаунту, под которым Desktop их хранит (он работает под своим входом), остальное —
к аккаунту, на который cswap переключил Claude Code к этому моменту (журнал
`~/.claude-swap-backup/claude-swap.log*`). Расход до начала журнала не относится
ни к кому и в таблицы не входит. Время сброса в сообщении об упоре называет
аккаунт независимо от журнала, и вкладка «Данные» показывает, сколько раз это
совпало. Запуски из сессии Desktop без её записи (`claude -p` арены, удалённые
сессии) считаются по аккаунту cswap: сверка это подтверждает, но доказательств
мало, поэтому их доля стоит в метках строки.

**Выход сабагентов.** У части ответов в транскриптах сабагентов нет финальной
копии, и записан только выход начала стрима (около 10 токенов), хотя содержимое
ответа есть. Выход оценивается по длине текста, аргументов вызова и подписи
размышлений; коэффициенты подбираются по законченным ответам той же модели. На
отложенных днях (04.10.2026) ошибка суммы — около 1% против 16% у среднего по
модели. Если примеров мало или подгонка плохая, берётся среднее.

### Точность

- Видно только то, что выполнялось на этом Mac. claude.ai, телефон и другие
  машины тратят те же лимиты незаметно, поэтому оценки «уровень» и «упор»
  занижены на эту долю (в вебе — до ~5% недели Max 20x). «Разность» от расхода
  до первого замера не зависит.
- «$ по API» зависит от смеси моделей и доли чтения кэша: четыре точных замера
  недели Max 20x дали $2,236–2,729, а без чтения кэша — $1,310–1,409. Поэтому
  недели лучше сравнивать по столбцу «без чт. кэша». Похоже, лимит считает
  чтение кэша намного дешевле прайса API; это гипотеза по нескольким замерам.
- Аккаунт в первые 60 секунд после переключения cswap и при входе мимо cswap
  (Orca, `/login`) известен неточно; доли такого расхода — на вкладке «Данные».
- Ряд процентов пишется, только пока открыт `limits`. Упоры в лимит видны
  всегда, а «разности» и перезапуску без упора нужны замеры. Для непрерывной
  записи можно запускать `limits --observe` по расписанию (launchd, раз в 5 минут):
  он один раз спрашивает cswap, дописывает наблюдения и выходит.

## Подписки

Для Codex читается **сохранённое** поле `chatgpt_subscription_active_until` из
метаданных входа; дата его проверки провайдером лежит в `limits --json`.
Это не свежий запрос в биллинг. Выбирается самая свежая проверка одного workspace;
дата не переносится на другой workspace. Срок токена и сроки reset credits
никогда не используются как дата подписки.

cswap не отдаёт дату продления Claude. Подтверждённые в Billing даты задаются так:

```sh
limits --set-subscription claude user@example.com 2026-10-14 --renews
limits --set-subscription codex user@example.com 2026-10-10
```

Первый вариант означает автопродление, второй — окончание известного оплаченного
периода. `--subscription-source` позволяет подписать источник. Это только
локальная запись даты, без оплаты и изменений подписки. Даты находятся в
`~/.config/limits/subscriptions.json` (права 0600); переопределение пути —
`LIMITS_SUBSCRIPTIONS`. После изменения даты перезапустите уже открытый экран.
Прошедшая дата выделяется пометкой «проверь» и не переносится на
следующий месяц автоматически. Если даты нет, выводится «нет даты подписки».

## Разработка

Исходная версия импортирована без изменений из OpenClaw integrations/limits.
Рабочая команда `~/.local/bin/limits` запускает `watch.py` из основной ветки этого
репозитория. `/opt/homebrew/bin/limits` — существующая ссылка на ту же команду.
Изменения делаются в отдельном worktree, затем сливаются в main.

```sh
/usr/bin/python3 -m unittest -v
```

Проверки покрывают потерянные/ошибочные аккаунты, частичный отказ CodexBar,
объединение профилей, разграничение workspace, возраст данных, даты подписок,
компактный вывод пяти аккаунтов в терминале 120×24, целый прогноз на ширине 80 и 100,
сброшенные по расписанию окна, последние данные и ошибки cswap, клавиши, выбор
аккаунта, переключение через cswap, кеш Codex и статистику: индекс транскриптов
(копии одного ответа, длины блоков, упоры в лимит, недописанная строка, подмена
файла, очистка старого), цены, журнал cswap (смена слотов, Activated, время чужого
входа), наблюдения (изменение и плато, второй процесс, тариф, сессии Desktop,
прежняя история), отрезки (упор, перезапуск, уровень и разность, окно Fable,
Desktop с записью и без, fast mode, конец расхода в момент замера), оценку выхода
по содержимому и вкладки экрана.
